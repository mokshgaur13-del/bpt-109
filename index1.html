Question 1 · Remembering

Four characteristics of a modern digital computer and five generations of computers

Four primary characteristics

  1. Speed: A computer performs millions or billions of operations per second, allowing calculations and data processing to be completed quickly.
  2. Accuracy: It produces highly accurate results when the data and instructions are correct. Incorrect input or programming can still cause errors.
  3. Storage capacity: It can store large amounts of data and retrieve it quickly using memory and storage devices.
  4. Automation and consistency: Once programmed, it can perform repeated tasks automatically and produce consistent results without becoming tired.

Five generations of computers

GenerationMain technologyKey development
FirstVacuum tubesVery large machines, high heat and power use; e.g., ENIAC.
SecondTransistorsSmaller, faster and more reliable than vacuum-tube computers.
ThirdIntegrated circuits (ICs)Many electronic components placed on a single chip.
FourthMicroprocessors using VLSIPersonal computers became widespread; processing power increased greatly.
FifthAI-oriented and advanced parallel processingEmphasis on artificial intelligence, natural-language processing and intelligent systems; the boundaries are not universally fixed.
Question 2 · Understanding

Flow of data, instructions and control signals in a computer

A computer system consists of the input unit, central processing unit (CPU), memory and output unit. These components work together under the control of instructions stored in memory.

Input Unit → CPU ↔ Main Memory → Output Unit
Control unit coordinates operations; data and instructions travel through system buses.

Functions of each component

  • Input unit: Accepts data and instructions through devices such as a keyboard, mouse or scanner and converts them into a machine-readable form.
  • Memory unit: RAM temporarily stores active programs, data and intermediate results. ROM/firmware stores essential startup instructions; long-term files are kept on SSDs or hard drives.
  • CPU: The control unit fetches and decodes instructions and sends control signals. The arithmetic logic unit (ALU) performs arithmetic and logical operations. Registers hold small amounts of data for rapid access.
  • Output unit: Presents processed information through a monitor, printer, speaker or other output device.
  • System buses: The data bus carries data, the address bus identifies locations, and the control bus carries signals such as read, write and interrupt.

Basic instruction cycle

  1. Fetch: The CPU retrieves an instruction from memory.
  2. Decode: The control unit interprets the instruction.
  3. Execute: The CPU performs the required operation, often using registers and the ALU.
  4. Store or output: The result is saved in a register or memory, or sent to an output device.

Example: When a student types marks into a spreadsheet, the keyboard sends input, the CPU executes the formula using data in memory, and the monitor displays the calculated result.

Question 3 · Application

Use of optical scanning and electronic card readers on a campus

A campus can automate attendance, library borrowing and access control by combining optical scanners with electronic card readers and a secure student database.

DeviceCampus useHow it works
Barcode scannerLibrary checkouts and inventoryReads the printed barcode on a student card or book and sends its identifier to the system.
OMR (Optical Mark Recognition)Multiple-choice tests and paper surveysDetects filled marks in predefined positions on a form.
RFID readerLibrary entry, attendance or access gatesUses radio waves to read an RFID tag or card without direct contact.
Smart-card readerSecure campus servicesReads data from a chip card; contact or contactless systems may be used.

Suggested workflow

  1. Issue each student a unique campus ID and register it in the authorised database.
  2. At a lecture, the student scans a barcode or taps an RFID/smart card at the reader.
  3. The system checks the ID, course schedule and time, then records attendance.
  4. At the library, scanning a book and student ID updates the loan record and due date.
  5. Staff review exceptions, such as failed scans or duplicate entries, and correct them through an authorised process.

Benefits and safeguards

Automation reduces manual entry, speeds up queues, improves record accuracy and makes books easier to track. The campus should protect student data with access controls, encryption, limited retention, audit logs and a manual alternative when a card or reader fails. A card scan should not be treated as proof that the student personally attended unless the process includes suitable checks.

Question 4 · Analysis

Low-level languages versus high-level languages

Low-level languages are closely related to a computer’s hardware. High-level languages use more human-readable instructions and usually provide greater abstraction from hardware details.

FactorMachine languageAssembly languageHigh-level language
FormBinary instructions (bits)Mnemonic instructions, such as MOV or ADDReadable statements, such as Python or C-style expressions
ExecutionExecuted directly by the processorTranslated by an assembler to machine codeCompiled or interpreted/translated, depending on the language and runtime
SpeedCan be highly efficient when well designedCan provide precise control and efficient codePerformance varies; optimising compilers can produce very fast code
Hardware dependenceVery highHigh; often processor-specificUsually lower, especially with portable runtimes
Ease of programmingVery difficult for humans to read and writeRequires detailed hardware knowledgeGenerally easier to read, write, debug and maintain
Common usesProcessor-level instructions and machine-code outputEmbedded systems, device routines and performance-critical sectionsWeb applications, business software, scientific programs and general software

Conclusion: Low-level languages are useful when precise hardware control is essential, while high-level languages are usually preferred for faster development, portability and easier maintenance. Actual speed depends on the program, compiler, runtime and hardware—not just the language category.

The best choice depends on software support, accuracy requirements, user training and the task; tablets do not automatically make every CAD workflow more accurate.

Question 6 · Evaluation

Plotter versus ultra-high-definition monitor and large-format printer for engineering blueprints

The choice depends on whether the main requirement is producing physical drawings or reviewing them digitally. A large-format printer is often practical for routine blueprint production; a plotter may be valuable for specialised line work, while a high-resolution monitor is best for digital inspection rather than physical output.

CriterionDrum/flatbed plotterUHD monitor + large-format printer
Line resolutionCan produce precise technical lines; quality depends on the plotter technology and pen/media.UHD monitor offers detailed on-screen viewing; printer quality depends on its DPI, ink/toner and media.
ScalabilityCan handle large drawings within its supported media size; specialised models may be less flexible.CAD files can be zoomed on screen; the printer can output supported sheet or roll sizes.
WorkflowUseful for specialised technical plotting and repeated line drawings.Supports digital review, collaboration, revisions and final paper copies.
Cost factorsInitial purchase, maintenance, specialised consumables and service.Monitor cost plus printer purchase, ink/toner, paper, maintenance and calibration.
LimitationsMay be costly or slower for mixed graphics and colour-filled documents, depending on model.Screen pixels do not determine printed resolution; printer settings and scale must be checked.

Recommendation

For a modern civil-engineering office producing varied CAD plans, choose a calibrated UHD monitor for inspection and collaboration plus a reliable large-format printer for final drawings. This combination is flexible and often easier to integrate into a digital workflow. Choose a specialised plotter when its particular line quality, media handling or workflow offers a measurable advantage.

Important: Before printing, verify drawing scale, line weights, paper size, margins and a test measurement. Long-term costs depend on print volume, consumables, maintenance and the equipment selected, so compare total cost of ownership rather than purchase price alone.
Question 7 · Evaluation

Reliability and security of facial recognition versus voice recognition in noisy public environments

Facial recognition identifies or verifies a person from facial features; voice recognition analyses voice characteristics. Both can be affected by environmental conditions, system design and the quality of enrolled data.

FactorFacial recognitionVoice recognition
Environmental reliabilityCan be affected by poor lighting, camera angle, occlusion, image quality and changes in appearance.Particularly vulnerable to background noise, reverberation, microphone quality, illness and changes in speaking style.
Public-space concernsCan capture bystanders without active participation; raises surveillance and consent concerns.May record nearby conversations; public noise can cause failed or incorrect matches.
Security risksPossible spoofing with photos, video or masks; presentation-attack detection helps but is not perfect.Possible replay or synthetic-voice attacks; challenge-response and anti-spoofing checks can help.
AccessibilityMay be difficult with some camera, lighting or mobility conditions.Can support hands-free use but may be unsuitable for speech impairments or noisy surroundings.
SafeguardsGood camera placement, liveness checks, testing across demographic groups and a non-biometric alternative.Noise-reducing microphones, secure phrase/challenge design, anti-spoofing and a non-voice alternative.

Assessment and conclusion

In a high-noise public environment, voice recognition is generally more directly affected by surrounding sound, while facial recognition may perform better if lighting and camera positioning are controlled. Neither method is perfectly reliable or secure, and performance differs across systems and users.

Biometrics should not be the only way to access essential services. Use encryption, restricted access, minimal data retention, clear consent and a fallback such as a secure card plus PIN. Test false-acceptance and false-rejection rates in the actual environment, and provide a human review or appeal route for failed matches.

Question 8 · Design

Accessible, hands-free computer workstation for a visually impaired user

The goal is to let a visually impaired user operate a computer independently using non-visual input and output, with minimal need for a mouse or visual feedback. The exact setup should be selected with the user because visual needs and preferences vary.

Recommended components

  • Computer and operating system: A reliable computer with built-in accessibility settings and support for assistive technology.
  • Screen reader: Software such as NVDA, JAWS or VoiceOver reads interface elements, text, menus and notifications aloud.
  • Speech input: A compatible speech-recognition tool allows hands-free dictation and voice commands. A good microphone and a quiet environment improve recognition.
  • Tactile keyboard: A standard keyboard with tactile key markers or a braille keyboard/display where appropriate. Keyboard shortcuts reduce dependence on pointing devices.
  • Speech output: Headphones or speakers provide spoken feedback; a refreshable braille display can provide tactile text output for users who prefer it.
  • Accessible software: Use applications that support keyboard navigation, labelled controls, meaningful headings and screen-reader accessibility.
  • Ergonomics and backup: Position the keyboard and microphone comfortably, manage cables, provide accessible power controls and maintain a backup method if voice input fails.

How the system works

Voice command / Keyboard → Computer + Accessible software → Screen reader / Speech synthesizer / Braille display

Example workflow

  1. The user wakes or starts the computer and signs in using an accessible, secure method.
  2. The screen reader announces the desktop and focused controls.
  3. The user navigates with keyboard shortcuts or voice commands and dictates text when suitable.
  4. The screen reader speaks typed text, menus, errors and document content; a braille display can present text tactually.
  5. The user saves work, confirms the action through spoken feedback and signs out securely.

Accessibility, privacy and testing

Give the user control over speech rate, voice, volume, keyboard shortcuts and braille settings. Voice commands should be optional because speech can be tiring, private information may be spoken aloud, and recognition may fail in noisy places. Use headphones for confidential content, avoid storing unnecessary voice recordings, keep software updated and test the workstation with the intended user before deployment.

Conclusion: Combining a screen reader and speech synthesizer with keyboard navigation, optional voice input and tactile output creates a flexible, accessible workstation. The best design offers more than one input/output method and is tailored to the user’s preferences.
